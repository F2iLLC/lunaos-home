# Luna 2.0 — integration and runtime verification

Status: shared character integrated in Home and the notebook, with a command-ready cue, aligned snoring mouth, and compact notebook drawer. Latest changes were rebuilt and installed on the Echo Show 8 and the Home and drawer were visually reviewed on 2026-11-11. Target-device performance profiling and reduced-motion verification remain open.

## Recoverable baseline

Starting commit: `823f8c0` on `feat/320-notebook-relay`. Recorded pre-integration suite: 458 tests, 287 pass, 85 fail, 86 skip. Failures include local socket EPERM, missing Java/native prerequisites and vault/native-store setup. These are baseline failures, not a green suite.

## Pre-integration architecture (recorded before the integration)

- `src/native.js`: Android-debug Tauri Home avatar, inline SVG; existing `get_luna_snapshot` polling drove capture-phase attributes, captions, notebook results and concurrent timer cards. Native commands owned all microphone/timer behavior.
- `src/index.html`: separate welcome companion and notebook SVGs. `src/notebook.js` showed server-reported outcome animations and performed notebook requests.
- `src/styles.css`: independent legacy animation families. Face base in Home is a 262 × 164 rounded rectangle, giving a wide face before animation. Eyes wake with scaleY(.08 → 1.12 → 1), deliberately stretching them. Sleep/snore uses unequal scaling. These explain geometry problems by inspection; they are not measured evidence of a frame-rate bottleneck.
- The previous commit already replaced Home's software blur with a radial gradient and avoided redundant state writes. Per-frame filters therefore cannot honestly be named as the current Home bottleneck. Polling still rebuilds timer cards every second while listening; this is a profiling candidate, not a proven cause.
- Existing polling is guarded against overlapping requests and stops on hidden documents/routes. Integration preserves those behaviors, the button, pressed state, keyboard focus, captions and separate text status.
- Before integration, `BackgroundWakeService` used RESPONSE during both online processing and playback, and `HomeLunaBridge` reported OFF when the service stopped, including mute/lock/permission/connection failures. The native snapshot now exposes explicit presentation telemetry for these cases without moving orchestration into the avatar.
- `scripts/android-offline-voice-probe/LunaFace.java` is a separate native diagnostic Canvas face, not the Home WebView SVG. It remains unchanged.

## Shared presentation architecture

A framework-free SVG module matches the existing plain JavaScript application. One fixed 320 × 360 coordinate system, fixed face geometry, stable groups, preset expressions, and CSS-only transform/opacity motion. No new dependencies, React, geometry morphing, filters, or frame loops. No SVG resource IDs are needed, preventing cross-instance collisions entirely. Wardrobes are presentation groups only.

The gallery is isolated from app events; build with `node scripts/build-luna-gallery.mjs` and open `docs/luna-2/gallery.html`. Its controls remain demonstrations, never real assistant events.

## Live application integration (2026-11-11)

- `src/luna/avatar.js` and `avatar.css` now render the welcome/Home and notebook avatars from the same stable SVG. The welcome avatar is mounted in the regular Home app; Android-debug Home moves the same host into the existing accessible listening button. The notebook route retains its existing server-owned list operations and displays the shared character for working, confirmed success, and error/uncertain outcomes.
- `src/luna/presentation.js` is a pure event mapper. The native snapshot remains authoritative; the avatar owns no timers, requests, audio, listening controls, or assistant state. `happy` is limited to notebook outcomes marked confirmed by `avatarForOutcome`; failed and uncertain requests map to `error`.
- Snapshot additions in `HomeLunaBridge` and the Rust bridge are `listeningEnabled`, `listeningStatus` (`disabled`, `enabled`, `permission`, `muted`, `locked`, `disconnected`), and `replyPlaying`. Deliberate disable maps to `sleeping` only when no higher-priority event is active; a ringing timer maps to `working`. Permission loss, mute, lock, service disconnection, and unavailable service map to `error`; capture `preparing`, `review`, and `retry` map to `thinking`; wake capture `waiting`/`awake` maps to `listening`; response processing maps to `thinking`; actual MediaPlayer playback maps to `talking`.
- `replyPlaying` is set only after native MediaPlayer `start()` succeeds and cleared on close/completion/error. The avatar uses its simple mouth motion during this true playback interval. There is no phoneme synchronization or measured audio-level signal in the current native path.
- The shared sleeping state has aligned closed/open snore-mouth shapes at one fixed position in front of the sleep mask. The smile is hidden while sleeping, and snoring swaps mouth visibility rather than scaling the mouth, so the curve cannot slide down the face. The gentle 1.5px/0.6-degree head bob remains. The typing forearm stroke increases from 2px to 5px. These are CSS animations, so the same hidden/offscreen pause and reduced-motion rules apply. Geometry does not change between states.
- Home shows an explicit command-ready pill only for the authoritative combination `status=ready`, `listeningStatus=enabled`, `capturePhase=awake`, and no ringing timer. The ordinary wake-word `waiting` phase retains its “Say Hey Luna” prompt. The listening control's accessible name announces the command window; reduced motion disables the pulse.
- The notebook popup rests at 28vh (capped at 30vh) as a bottom drawer with a dedicated scroll area. Its handle expands on an upward pointer drag or click/keyboard activation; a downward drag at the top of the expanded drawer collapses it. Full-screen mode exposes “Open full notebook to edit,” which closes the dialog and navigates to the existing editable `#notebook` route. List data remains scrollable and authoritative. Entry and expansion/collapse respect reduced-motion settings. The closed dialog has an explicit `display:none` rule, verified in the target WebView.
- Static server routes now expose the shared module and stylesheet. `scripts/build-native.mjs` copies the stylesheet into the native bundle. Existing Home voice controls, captions, accessibility labels/status, notebook and checklist requests, timer cards/countdowns/cancellation, navigation, error messages, and overlapping snapshot protection remain in their existing modules.
- Added Home snapshot mapping tests, notebook outcome mapping coverage, independent-instance/resource checks, outfit-change coverage, sleep/typing assertions, and drawer click/drag/route tests. After merging current `main` timer pause/resume work, the targeted run passed **27/27** (`node --test test/luna-avatar.test.js test/luna-presentation.test.js test/native-status-polling.test.js test/notebook-popup.test.js test/android-vault-wiring.test.js`). `npm run build:native` passes.
- Latest full suite after the merge: **478 tests, 356 passed, 36 failed, 86 skipped**. Failure labels match the preceding integration run (37 markers in each), with no added or resolved labels. The suite is **not clean**. The recorded baseline had 85 failures and 86 skips (the current failure count differs). Local Java/keytool/JDK-dependent cases remain unavailable on this Mac.
